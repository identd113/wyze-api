# Release notes: wyze-api 2.0.0-beta.2

Published to npm on 2026-08-29 under the `beta` tag. The tag is `v2.0.0-beta.2` (`e313ab3`), 14 commits after `v2.0.0-beta.1`.

**Pairs with:** `homebridge-wyze-smart-home@2.0.0-beta.2`.

This release brings the fixes that had only landed on `main` into the 2.0.0 line. `main` kept the monolithic `index.js` and `2.0.0` had already been split into modules, so it was a manual reconciliation, not a mechanical merge.

## What changed

- **TLS root pinning** (`src/httpsAgent.js`, bundled DigiCert roots). Fixes `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` on Node 24.18.0 and newer, where the root-store update dropped the legacy DigiCert Global Root CA that `api.wyzecam.com` and `yd-saas-toc.wyzecam.com` chain to. It is set on `axios.defaults.httpsAgent` so every file that requires axios gets it.
- **Ford API lock signing** for the original Wyze Lock (`YD.LO1`): `getLockInfo` now signs its GET parameters, and the token field is `access_token` for GET and `accessToken` for POST. Fixes `PARAM_SIGN_INVALID` and `PARAM_TIMESTAMP_INVALID`.
- Camera streaming fixes: `Date.now()` instead of `moment().valueOf()`, a missing `this.` on the `runActionList` fallback, and the unused `moment` dependency removed.
- `DX_PVLOC` (Palm Lock) was registered in both `LockBoltV2Models` and `CommonModels`, so it could be routed to the generic switch handler. It is now only in `LockBoltV2Models`.
- Typo fix in the `package.json` description.

## Breaking changes

None.

## Known gaps at release

- Still no `engines` field and the `werift` audit findings from beta.1 (both fixed in beta.3).
- The TLS pin is a workaround for Wyze's certificate chain. Whether it can be dropped depends on `app.wyzecam.com` serving the same calls (open item in `TODO.md`).
