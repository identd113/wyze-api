# Release notes: wyze-api 2.0.0-beta.4

The changelog is written for people using the library. This page is for whoever ships and supports it: what changed in the code, what has been checked on real hardware and what has not, and what is known to be unfinished.

**Compared against:** `v2.0.0-beta.3` (`8d3eef1`, published 2026-10-26), the last published release. `beta.4` is 40 commits and 90 files (+3,728 / -248 lines, without the lockfile) on top of it, not counting the release commit itself. Always compare against the last *published* release, not against the working branch.

**Pairs with:** `homebridge-wyze-smart-home@2.0.0-beta.4` (see that repository's `docs/releases/2.0.0-beta.4.md`). The plugin's newer features need this release: with `wyze-api` beta.3 they switch themselves off (the plugin logs one warning for the bulk read).

## Breaking changes

None for the public methods: nothing that 1.1.15 or beta.3 offered was removed or reordered. Two things to know:

- **The TUTK and GUTES code is no longer in the package.** `src/tutk/` and `src/gutes/` moved to `future/`, which is tracked in the repository but not published. Nothing in the library used them. Code that imported `wyze-api/src/tutk/...` or `wyze-api/src/gutes/...` must take it from the repository.
- **`koffi` and `querystring` are no longer dependencies.** `koffi` was needed only by the TUTK code, which now declares it in `future/tutk/package.json`. Nothing used `querystring`. A project that relied on getting either through `wyze-api` must install it itself.

## New public API

| Method or option | What it does |
|---|---|
| `getPropertyListForDevices(devices, pids)` | The properties of many devices in one request (`app/v2/device_list/get_property_list`). Returns a `Map` from MAC to rows. Throws when Wyze answers with a different number of devices than were asked for. |
| `cameraGetEvents` / `cameraGetEventsMulti` option `types` | Ask Wyze for only some event types, by `EventAlarmType` name (`["SOUND"]`). Without it every type comes back. |
| `cameraGetEvents` / `cameraGetEventsMulti` option `tags` | Only events carrying an AI tag (`["PERSON", "PACKAGE"]`). |
| `ageMs` on each event | The event's age by Wyze's own clock, so it is right even when the host clock is off. |
| `getCamPlusPlans()` | The account's Cam Plus plans: status, end date, seats and the cameras each one covers. Expired plans are included. |
| `getPlanBindingListByUser(groupId = "hms")` | The plan group is now a parameter; `"cam-plus"` returns the camera plans. The default is unchanged. |
| `persistPath` default | Tokens are saved to `$WYZE_API_PERSIST_PATH`, else `~/.wyze-api`, when no `persistPath` is given. A client built without one used to fail at login. The folder is created owner-only. |

`cameraGetEvents` and `cameraGetEventsMulti` throw on a `types` or `tags` name they do not know. A typo used to be dropped quietly, and an empty filter means "everything".

## What changed in the code

### Requests and login (`src/index.js`, `src/util/security.js`)

- `maybeLogin()` shares one in-flight login between concurrent callers. Before, a second caller could start a second login while the first ran, the second was not awaited (a failure became an unhandled rejection), and a one-shot 2FA code failed on the repeat.
- Requests to Wyze hosts get a 30 second timeout when the caller set none (an interceptor next to the existing redirect guard, Wyze hosts only). Before, a stalled connection hung login and everything that waited on it. The camera thumbnail download has its own 15 second timeout and a 20 MB size cap.
- Tokens are saved to `~/.wyze-api` by default (above). The probe scripts use the same default instead of saving next to themselves, and the package no longer includes `scripts/wyze-*.json`.

### Cameras (`src/devices/cameras.js`, `cameras.helpers.js`)

- A HomeKit stream whose ffmpeg cannot start (binary missing or not executable) now ends with a logged reason. The `error` event of the two spawned processes was not handled, so it was thrown and took the host process down.
- `cameraWarmUp` does nothing and resolves `false` while a live stream of that camera is open. It used to claim the camera's single connection slot and close the stream.
- The event list gained `types`, `tags` and `ageMs` (above).
- The Cam OG Telephoto 3x is `GW_GC2`, not `GW_GC`.
- The unused `bitrate` option of `startCameraHKStream` is gone. The video is stream-copied, so a requested bitrate was always ignored.

### Packaging and project

- `src/tutk` and `src/gutes` moved to `future/` (each with its README, tests, and for TUTK a Docker smoke test). `npm run test:future` runs their tests.
- `package.json` `files` takes `scripts/*.js` and `scripts/README.md`, not the whole `scripts/` folder. A test packs the package and fails if it would hold a token file, `.env`, `CLAUDE.md`, `future/` or `tests/`.
- ESLint (`.eslintrc.json`, `npm run lint`) over `src`, `scripts` and `tests`, with a CI job. The published code changed only by comments explaining four intentional cases.
- `docs/downstream.md`, `docs/releasing.md` and the contributor index `docs/README.md` are new. `follow-redirects` is 1.16.2 in the lockfile.

### Tests

- `tests/compat-1x.test.js` pins what 1.1.15 offered (public method names, parameter names in order, the options of an options-object parameter, exports, what its pure methods return) and fails if a change drops any of it. Intentional differences are listed in the test with the reason and in `docs/downstream.md`.

## Quality and care

- **Tests:** 354 tests pass in 39 files, with none skipped. Each fix in this release has a test that fails without it.
- **Lint:** ESLint runs on `src`, `scripts` and `tests` with zero warnings allowed, locally and in CI. The published code changed only by four explanatory comments.
- **Backward compatibility:** `tests/compat-1x.test.js` pins the 1.1.15 surface (189 methods with their parameter names, order and options keys, 15 exports, what the pure methods return) and fails on any drop. It was itself tested with deliberate breaks (a swapped parameter, a rename, a removed option). The few intended differences are listed with reasons in the test and in `docs/downstream.md`.
- **Same answers as 1.x:** the read-only getters were run on a real account under the published 1.1.15 and under this branch, with the same response shapes.
- **Review:** a code review of both repositories, one reviewer each, was done before release. The highest findings were checked by hand and fixed (the login race, the ffmpeg start failure, request timeouts, the compatibility test). The rest are under Known issues.
- **Dependencies:** `npm audit --omit=dev` reports no vulnerabilities, and two unused dependencies were dropped.
- **Package contents:** a test packs the package and fails if it would hold a token file, `.env`, an agent file, `future/` or `tests/`.

## What has been checked, and how

### Checked on real hardware (read-only calls, test account)

- The same read-only getters under the published 1.1.15 and under this branch return responses of the same shape: `getDeviceList`, `getObjectList`, `getDeviceGroupsList`, `getDeviceSortList`, `getUserProfile`, `getPlanBindingListByUser`, and `getPropertyList` and `getDevicePID` for a Cam v2, a Cam v3 and a doorbell. Both return the same 10 devices. Only shapes were compared, not values. This is not repeated by the test suite.
- `getCamPlusPlans` / `getPlanBindingListByUser("cam-plus")` against a real account with one active plan, matching what the cameras actually do (the covered camera gets video and AI labels, the others a picture about every five minutes).
- The bulk property read and the event list (with `types` and `tags`) have been in use by the plugin on a test bridge with four cameras since late October.

### Unit tests only

- The shared login (concurrent callers, a failed login with nothing unhandled), the ffmpeg start failure (a stubbed missing binary, with the process surviving), request timeouts (the interceptor on a Wyze host, another host, and a caller's own timeout), unknown event names, the warm-up skip, the token location and folder permissions, the compatibility test (with deliberate breaks to prove it fails), and the package contents.

### Not verified on hardware

- The ffmpeg failure path with a real missing binary, and the 30 second timeout against a really stalled connection.
- `cameraWarmUp` skipping while a real stream is open.
- Face and other rare AI tags in real event lists.
- `GW_GC2` (Cam OG Telephoto 3x): no such camera is on the test account, and its property list is reused from the OG camera.
- Network methods other than the read-only ones above, compared with 1.x.

## Known issues

- `getPropertyListForDevices` matches rows to devices by position and checks only that the counts agree.
- `ageMs` is not a number when an event has no time; callers should treat that as "age unknown".
- The audio gap filler in `rtpReorderBuffer.js` is PCMU silence and its timestamp step assumes PCMU, so a camera that negotiates Opus gets the wrong filler after packet loss. A backward jump in the RTP sequence (a camera re-sync) drops later audio until it wraps.
- Wyze's smoke and CO event types are known to the library but have never been seen in real data.

## Releasing

See [releasing.md](../releasing.md). In short: publish this package first as a GitHub pre-release (the `beta` tag), approve the staged publish on npmjs.com, check `npm view wyze-api dist-tags` (`beta` moves to `2.0.0-beta.4`, `latest` stays on 1.1.15), then release the plugin.
